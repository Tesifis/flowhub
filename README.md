# FlowHub 1.0 — мобильная PWA

## Что работает

- Мобильный главный экран: дата, расписание по дням недели, выделение текущей пары, задачи на сегодня / ближайшие / без срока.
- Добавление, изменение, выполнение и удаление задач; ручное расписание.
- Привычки с числовыми целями (страницы, минуты, количество) и отметкой «выполнено»; недельная статистика, 28-дневный календарь.
- Светлая, тёмная и системная темы.
- Локальное сохранение данных, резервная копия JSON, работа без интернета после первой загрузки через HTTPS.
- Опциональная авторизация и синхронизация нескольких устройств через собственный Supabase-проект.

## Как запустить

Это статический сайт. Не требуется сборка. Для локальной проверки в папке проекта выполните `python -m http.server 8000` и откройте `http://localhost:8000` на компьютере. В мобильном браузере PWA устанавливается после публикации по HTTPS.

## Постоянный адрес через GitHub Pages

1. Создайте отдельный репозиторий `flowhub` в GitHub. Загрузите в корень **все файлы** из этой папки (саму папку отдельно создавать необязательно).
2. В репозитории выберите Settings → Pages → Deploy from a branch → `main` → `/ (root)` → Save.
3. После публикации сайт будет доступен по адресу `https://ВАШ_ЛОГИН.github.io/flowhub/` (если репозиторий называется `flowhub`).
4. На Android откройте адрес в Chrome → меню → «Добавить на главный экран» / «Установить приложение».

Важно: GitHub Pages публично раздаёт исходный код, поэтому **не добавляйте в репозиторий пароли, service_role keys или личные данные**. Личные записи хранятся локально в браузере либо в вашей защищённой базе.

## Синхронизация через Supabase

1. Создайте проект Supabase.
2. Откройте SQL Editor и выполните весь файл `supabase.sql`. Он создаёт таблицу `flowhub_state` с RLS — каждый пользователь может читать/писать только свою строку.
3. В Supabase: Project Settings → API (или Settings → Data API) скопируйте URL проекта и **publishable / anon key** (только публичный ключ, никогда не `service_role`/secret key).
4. Откройте FlowHub → ⚙ → введите URL, ключ, email и пароль → «Регистрация». Если Supabase требует подтверждения email, подтвердите письмо и затем нажмите «Войти».
5. Повторите вход с тем же email на втором устройстве. Приложение пытается автоматически синхронизировать данные после изменений, при возвращении на вкладку и при восстановлении интернета. Можно нажать «Синхронизировать сейчас».

### Текущие ограничения версии 1.0

- Расписание пока **вводится вручную**; автоматическое получение из приложения/сайта МГТУ не подключено. При необходимости добавим импорт или отдельный парсер после проверки доступного источника.
- Без Supabase данные находятся только в браузере конкретного устройства; экспортируйте резервную копию перед очисткой браузера.
- Offline-режим активируется после первой успешной загрузки по HTTPS (Service Worker); приватный режим и очистка данных браузера могут удалить локальные записи.
- Синхронизация использует объединение записей с метками изменения и одну облачную JSON-строку. При **одновременном редактировании на двух устройствах** возможна потеря изменений (последняя отправка перезаписывает снимок). В следующем обновлении лучше перейти к построчной синхронизации и очереди изменений.
- Сессия авторизации хранится только в текущей вкладке (sessionStorage). После нового запуска браузера может потребоваться повторный вход.
- Напоминания, автоматическое недельное push-уведомление и интеграция Google Keep отсутствуют. Недельная статистика считается и показывается в самом приложении.
